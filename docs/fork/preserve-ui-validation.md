# Mikova 原界面融合验证

## 新增

- 原设置中的账号连接、任务队列、语音、微信、本地钱包、自托管连接和虚拟屏入口。
- 语音单一粒子交互区、输入/朗读状态、草稿保存、音色读取与试听；设备没有声源方位信息时明确显示不可用。双声道能量差不当作物理方位。
- 独立音频与 HTTP 核心测试，不触发完整 Compose 编译。

## 改动

- 默认保留原 Mibot 聊天、五 Tab、侧栏和 glass 设置布局。V7 兼容链接返回真实页面。
- 动态使用真实 Feed；任务使用真实注册表/本地队列状态，不显示虚构进度。
- 自托管明确为连接配置/HTTP 连通性诊断，不宣称已实现远端任务、数据同步或 Computer Use。

## 修复

- APK 测试探针支持选中 Tab（不重复点击），点击坐标服从所有父容器可见边界，屏外入口滚动查找。
- 实测发现进入虚拟屏触发 `UiText.source is not installed`。现从 Application.attachBaseContext 安装 Mika ResourceTexts，读取本体语言资源，早于手机/任务单例初始化。
- ACRA 捕获的进程崩溃纳入 smoke 门禁，不能因没有 FATAL EXCEPTION 而误记为无崩溃。
- 不再为每次修改截图脚本重新构建 APK；复用时校验生产源码树一致并记录 APK 哈希与来源。

## 已知问题

- 当前微信桥读取授权后的通知文字。没有公众号/视频阅读、自动回复或完整 Goal 执行器。
- 钱包没有支付通道。自托管没有远端执行协议/数据迁移。
- 语音为点按打断，免触控全双工尚未实现。设备系统语音包、麦克风、sherpa 运行库和模型须实际就绪；不能承诺每台设备离线识别/合成。
- 虚拟屏页面可用不等于可信隐藏屏执行通过；真实配对、权限、第三方 App 操控需要设备验收。
- 当前签名仍来自 CI debug key，不保证覆盖手机旧版；不执行卸载或清除用户数据。
- 本轮 UI 验收使用干净模拟器，无真实账号和密钥；侧栏演示数据明确是 debug fixture。
