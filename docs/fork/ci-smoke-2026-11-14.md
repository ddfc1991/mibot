# Mikova CI smoke 修复（2026-11-14）

## 新增

- 构建前运行 `.github/ci/test_smoke.py`：用 fake adb/aapt2 执行真实 smoke.sh 和 tap.py，覆盖 APK applicationId、安装确认、启动退出码、退出码为 0 的 Error type 3、后续深链接/中文/VD 启动失败、进程退出和 crash 门禁。
- 所有退出路径保存 logcat/crash；失败另存 Activity/Window 状态、UI XML 和现场截图。

## 改动

- 从构建产物的 `aapt2 dump badging` 读取 applicationId，找不到工具、读不到元数据或没有合法包名均失败，不回退旧包名。Activity 类仍为 `com.openminis.app.MainActivity`。
- 安装后使用 `pm path` 验证目标包；进程、深链接、force-stop、pm clear 与外部文件路径均使用产物包名。
- 启动、重启与深链接统一检查 ActivityManager 返回码和错误输出。启动失败、进程死亡或必测入口缺失立即停止后续 UI 遍历。
- 默认首页先截图，再通过真实“原功能”入口进入原 glass 界面；保留英文侧栏与 Feed/Ideas/Group chats/Settings、中英文主题、设置和插件页面覆盖。

## 修复

- 旧脚本硬编码 `com.dl1991.mibot`，而 APK 为 `com.mikova.app`，导致 API 30/31 报 Activity 不存在却继续截图。
- `am start` 退出 0 但 stderr 出现 `Error type 3` 的错误现在会使 smoke 失败，并上传诊断。

## 已知问题

- 现有 V7 首页及部分功能仍是仓库已有的 compiling stub。本修复未新增 stub，也未将这些入口标记为功能完成。并行设计分支的最新 UI 未包含在此 APK。
- 真机旧版与此前 CI APK 的签名不一致，覆盖安装返回 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。稳定签名与保留数据升级需另行核对，本次 smoke 不证明真机可覆盖升级。
- DSH 真机宿主能力仍受 x86_64 模拟器的 ARM native bridge 限制，原有 best-effort 探针不等同端到端成功。
- `ci_vd_usb` / `ci_vd_demo` 已在 MainActivity 中被忽略；原脚本的 VD 探针仍保留，但不代表 Mika 新虚拟屏能力已端到端验收。

## 验证

- 旧脚本红灯：`python3 .github/ci/test_smoke.py SmokeTest.test_start_error_with_zero_exit_status` 确认报错后仍产生 `01-chats.png`，回归失败。
- 本地验证命令：`bash -n .github/ci/smoke.sh`、`python3 .github/ci/test_smoke.py`、`python3 .github/ci/check_new_locale_keys.py`、`git diff --check`。
- 完整 Android workflow 必须实际执行 Build debug APK、API 30 和 API 31 smoke；最终状态以对应 GitHub Actions run 为准，不以快测试替代模拟器结果。
